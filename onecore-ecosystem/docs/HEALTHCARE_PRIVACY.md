# Healthcare privacy and access controls

The healthcare API is a protected clinical-record slice, not a declaration of regulatory
certification. PHI profile and encounter-note JSON is encrypted with Fernet before it is
persisted. Set HEALTHCARE_PHI_ENCRYPTION_KEY to a dedicated Fernet key generated by
`Fernet.generate_key()`; store it in a secret manager, back it up separately, restrict
access and rotate only with a tested re-encryption procedure. The API fails closed for
PHI operations if the key is missing or invalid. Never use a development key in production.

All healthcare records are organization-scoped and branch-scope filtered. Healthcare
administrators and org administrators administer records and access grants. Physicians
and nurses require active patient-specific grants for read/write; grants can expire and
be revoked. Clinical auditors are read-only and must provide an audit reason. Access,
record reads/writes, encounter reads, consent changes and grant changes create patient-
linked audit events. Consent decisions are append-only rows; do not overwrite prior
decisions. The API intentionally returns 404 for records outside the active tenant or
branch to avoid disclosing their existence.

Endpoints:
- POST /api/v1/healthcare/patients and GET/PUT /api/v1/healthcare/patients/{id}
- POST /api/v1/healthcare/patients/{id}/access; POST /api/v1/healthcare/patients/{id}/access/{grant_id}/revoke
- POST/GET /api/v1/healthcare/patients/{id}/encounters
- POST /api/v1/healthcare/patients/{id}/consents
- GET /api/v1/healthcare/patients/{id}/audit

Deployment controls still required before real patient data: enforce TLS everywhere; use a dedicated secret manager and key rotation/recovery drill; configure database and backup encryption; private object storage; least-privilege database accounts; MFA and short sessions; tested restore; monitoring/alerting; retention/deletion and data-subject request workflows; incident/breach response; signed processor agreements; penetration testing and Kenyan Data Protection Act / ODPC and applicable health-sector legal review. This implementation does not provide certified HIPAA/ISO compliance, consent identity verification, clinical validation, emergency break-glass workflow, or production key management.
